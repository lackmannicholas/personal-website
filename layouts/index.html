01Internal agent platformIn progress · GA targeted Q1 2027Runtime / Release / Memory

Agent Platform

Teams own what an agent does.
The platform owns how it runs.

The mandate was one sentence: teams need to build and ship an agent in four hours. Every product team building an agent was re-solving the same undifferentiated problems: voice transport, observability, sessions, and release. The platform separates agent configuration from agent execution so those problems get solved once.

Product teams own prompts, tools, and configuration. The platform owns execution, versioning, eval-gated release, and deployment. Engineers can work from their own repositories through a code-first plane, and release control is chosen per agent: a demo agent ships with a click, while agents handling payments and personal data ship through an engineering-owned path.

My role

Co-owner and one of two technical owners, accountable for the whole system. Primary author of the real-time voice plane, runtime deployment strategies, shared memory and sessions, and the code-first interaction plane.

02Real-time agent systemsVoice / Streaming / Latency

A voice agent is
a systems problem.

I built the foundation of the agent harness behind Lumina Workforce, part of RealPage’s publicly launched Lumina AI Suite: orchestration, voice transport, and agent runtime. It handles about 7,000 live calls a day. Nobody asked for the audio gateway; I identified the pattern and pushed to build it because it stabilizes voice latency and quality.

The hardest problem was latency, which turned out to be performance engineering across the whole real-time path. One voice activity detection change, run as a controlled A/B test, cut latency by 689 ms (p < 0.001, Cohen’s d = 1.04).

03EvaluationEvals / Quality signals

Evals for output
with no ground truth.

Fixing latency raised a bigger question: why couldn’t we see when voice quality was getting worse? Voice output has no ground truth and nothing practical to label. I proposed and designed a reference-free, three-layer audio eval suite and took it from a CLI prototype into our eval stack.

Public reference implementation: github.com/lackmannicholas/voice-evals

Three evaluation layers

  • Layer 1Acoustic & perceptual quality
  • Layer 2Conversational dynamics
  • Layer 3Audio LLM-as-judge

Reference-free and unsupervised: zero per-clip labeling.
