01Internal agent platformIn progress · GA targeted Q1 2027Runtime / Release / Memory

Agent Platform

Teams own what an agent does.
The platform owns how it runs.

The mandate was a single sentence: teams need to build and ship an agent in four hours. Meanwhile, every product team building an agent was re-solving the same undifferentiated problems: voice transport, observability, sessions, and release. The Agent Platform separates agent configuration from agent execution so those problems get solved once.

Product teams own prompts, tools, and configuration. The platform owns execution, versioning, eval-gated release, and deployment. Release control is chosen per agent: low-risk agents can ship with a button click, while agents that handle payments and personal data use CI-gated releases.

My role

Co-architect and co-owner of the platform. I own the real-time voice plane, sessions, and long-term memory (Mem0), and designed the code-first SDK and Google Enterprise Agent Platform paths.

Ownership contract

  • In buildAgent identity · cost governance

A deployment is a versioned release of agent configuration, evaluated before it reaches production.

Status

Every RealPage product team was mandated onto the platform. GA is targeted for Q1 2027, with a roughly 30-engineer build-out staffed around the design.

Inside the work

The design tension

The platform supports button-click releases for low-risk agents and CI-gated releases for agents handling payments and personal data.

Why it exists

Product teams were rebuilding the same voice transport, tracing, sessions, and guardrails. A shared runtime gives them those capabilities once.

Netflix relevance

03Real-time agent systemsVoice / Streaming / Latency

A voice agent is
a systems problem.

I built Agentix, the orchestration framework for RealPage’s production leasing AI voice agent, and led the product from prototype to GA. It currently handles about 6,000 calls a day, with 400,000+ units onboarded.

Profiling and optimizing the full audio pipeline cut median response time from about five seconds to about three seconds. In a separate 100-turn controlled study, local VAD reduced substantive-turn latency by 689 ms (22%; p < 0.001, Cohen’s d = 1.04).

My contribution

Agentix orchestration, telephony WebSocket integration, real-time audio, and latency diagnosis across the pipeline.

04Evaluation infrastructureEvals / Quality signals / Replay

Evals for output
with no ground truth.

Fixing latency raised a bigger question: why couldn’t we see when voice quality was getting worse? Voice output has no ground truth, so it needed reference-free quality signals.

I originated reference-free audio evals for voice output and brought them into production. The suite uses DNSMOS, turn-taking measures, and audio LLM-as-judge.

The Agent Platform also uses eval-gated versioned releases.

Public reference implementation: github.com/lackmannicholas/voice-evals

My contribution

Reference-free audio evals originated and brought into production.

Three evaluation layers

  • Layer 1Acoustic & perceptual quality (MOS predictors)
  • Layer 2Conversational dynamics
  • Layer 3Audio LLM-as-judge

Reference-free quality signals for voice output without ground truth.

Result

Reference-free audio evals now run in production.
